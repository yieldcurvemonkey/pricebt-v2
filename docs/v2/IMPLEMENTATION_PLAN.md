## 0. Ground rules (every task, every agent)

### 0.1 The five MUSTs, restated (DESIGN §2.1)

1. **No external pricing or market-data dependency in `src/pricebt`.**
   - No import, name, special case or shape of ARBS, rateslib, QuantLib, gs_quant or any vendor.
   - Allowed dependencies: stdlib, numpy, pandas, PyYAML, python-dateutil, tqdm.
   - The guards in `tests/guards/` must pass after every task.
2. **The API is 1:1 with `gs_quant.backtests`.**
   - Same module paths, class names, real constructor signatures, field order and defaults, enum values, result shapes and column names.
   - The only allowed differences are the DEV-* rows of DESIGN §11.
   - The referee is `tests/test_gs_api_parity.py`.
3. **One asset config file per asset.** pricebt never interprets instrument kwargs.
4. **Multi-currency** via FX configs; risk in currency per bp; the `pnl_bps(risk)` view.
5. **No asset-class special-casing** in the engine, the pricing layer or the results. Swaptions later must be config-only. A toy swaption runs in CI.

### 0.7 Definition of done (for any task)

1. **Ownership.** The owned files exist, and nothing outside the owned list or the named shared edits was changed.
2. **Tests pass.** The task's acceptance command passes, **and** `tests/guards` passes.
3. **Tests can fail.** New logic has tests that fail when the logic is broken. For each task:
   - mutate one line of the new logic, with `tools/mutcheck.py` or by hand followed by a restore;
   - confirm that a named test fails;
   - record the mutation and the failing test in the report.
4. **Report.** The task report (the agent's final message) lists:
   - files created or changed;
   - tests added;
   - the acceptance summary line;
   - the mutation-check result;
   - open questions.

   **A report is a claim.** The phase gate re-runs everything.

**Ultracode workflow recipe (one workflow per phase):**
1. One implementation agent per task, in parallel where the table allows. Give each agent its owned-file list and a pointer to its task section here.
2. For each finished task, one **adversarial verifier** agent. It re-runs the acceptance command, reads the diff against the cited DESIGN and research sections, and tries to refute "done". It looks specifically for MUST-1/MUST-2/MUST-5 violations, gs behaviour changed without a DEV marker, and tests that cannot fail.
3. A fix loop until the verifier passes.
4. The main loop runs the phase gate itself (it never trusts reports), then commits.

Keep each phase to ≤10 agents.

### P1.5 Toy library and toy configs (tests only; never shipped)
**Owns:** `tests/toylib/__init__.py`, `tests/toylib/rates.py`, `tests/toylib/swaption.py`, `tests/assets/toy_usd_irs.yaml`, `tests/assets/toy_eur_irs.yaml`, `tests/assets/toy_usd_swaption.yaml`, `tests/assets/toy_fx.yaml`, `tests/test_toylib.py`. **Shared edit:** add `toylib.rates.reset_recorders()` to the conftest isolation fixture.
**Read:** DESIGN §4, §7, §13, Appendix A (mirror its shape); IMPLEMENTATION_PLAN §0.6.
**Build:**
- **`rates.py`**: a deterministic closed-form rates world, plus the recorders of §0.6.
  - The market for date `d` is `ToyCurve(ref_date, ccy, zero_rate)` with `r(d) = base + amp*sin(2π·n/period)`, where `n` is the business-day index since 2020-01-01, and `base`, `amp`, `period` are set per currency. This makes mean reversion trigger. The market function returns `None` for dates in `HOLES`.
  - `resolve_swap(market, kwargs)` pins dates and ATM. It accepts `pay_or_receive`, a tenor or date `termination_date`, an optional `effective_date`, `notional_amount`, and `fixed_rate` given as `'ATM'`, `'ATM±x'` or a decimal.
  - `build_swap(market, resolved)` returns a `ToySwap`: annual fixed coupons against a floating leg valued as `N·(DF(eff) − DF(mat))`.
  - Functions: `npv` (payer positive when rates rise), `pv01` (`N × annuity × 1e-4`), `par_rate` (bp).
  - `delta_ladder(market, trades, weights, tenors)`: each trade's PV01 goes to the nearest pillar; the result is linear in the weights.
  - Every entry point increments `EVAL_COUNTS[...]`. The market function appends `('market', d, csa)` and resolve appends `('resolve', d, csa)` to `CSA_SEEN`.
- **`swaption.py`**: about 25 lines of Bachelier with a flat normal vol.
  - The market is `SimpleNamespace(curve=ToyCurve, sigma=σ(d))`.
  - `resolve_swaption` pins `expiration_date`, `termination_date` and the strike (`'ATM'`, `'A-50'`, decimal), and folds `buy_sell` × the sign of `notional_amount` into a signed notional.
  - Functions: `npv`, `vega` (per bp of normal vol).
- **Configs:**
  - `toy_usd_irs.yaml` and `toy_eur_irs.yaml` follow DESIGN Appendix A's structure. They import `toylib.rates`, use `build_on: each_market` for USD and `resolve_date` for EUR (so both modes are exercised), and map `IRDelta: {scalar: dv01, bucketed: delta_ladder}`.
  - `toy_usd_swaption.yaml`: `instrument: IRSwaption`; `attributes: {expiration_date: ...}`; `risk_measures: {Price: npv, IRVega: {scalar: vega}}`.
  - `toy_fx.yaml`: `EURUSD = 1.10 + 0.01·sin(...)`, with the inverse supported.

**Tests** call toylib directly, not through pricebt:
- a par swap has npv ≈ 0; pv01 is positive for a payer;
- `sum(delta_ladder([t],[1])) == pv01(t)`; the ladder is linear;
