### 15.2 The cold-start test

A fresh agent was given only the skills and a fictional service library (`zeta`, documentation but no source) and a private copy of the repository. It wired the adapter, and all six outcomes held: adapter written, Kit conforms, layer kit passes, tie-out passes with the shipped tolerances and nothing declared, negative controls written, guards updated. It reported 17 friction items (wrong order of the guards step, no copy command, a partial `data/fixtures` failing instead of skipping, a service without data not covered, a fixed pillar set, dv01 of a started swap, upload accounting with layers, the cash window, the L0 float tolerance, `mutcheck` overriding `PYTHONPATH`, the documents table for an adapter outside `src`, the order of the conventions document, 237 KB of skills, `--stack` syntax, `python -m` versus a script on `sys.path`, a service variant of the wrap test template, the mapping worksheet). All 17 were fixed in the skills and verified by an independent skeptic who ran the commands; 16 residual defects it found (a wrong PowerShell explanation, two contradictory measured numbers, a fast-path tie-out that fails for a fixed-pillar library, an upload formula missing the cash world, stale counts, ...) were fixed and pinned. The qualification that the solver reported stays documented: against a library whose risk pillars are fixed and differ from the reference's, the reference must be aligned by a second overlay (changing only `tenors`); against the plain reference overlay the tie-out fails on `L2.dv01` (1.05e-4 relative on a seasoned 2Y, tolerance 1e-4), which is a different risk curve, not a bug, and is not declared as a tolerance.
