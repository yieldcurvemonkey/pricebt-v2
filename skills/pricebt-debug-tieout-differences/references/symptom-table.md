# Symptom -> likely cause -> probe -> fix

Rows marked `[control]` were reproduced with the worked example's negative controls (`skills/pricebt-wire-external-library/example/config/mistakes/`); `[QL doc n]` cites a measured section of
`docs/design/11-quantlib-conventions.md`; `[ledger]` cites `tasks/tolerance_ledger.yaml`; `[suite]` cites `tasks/suite_reproduction.md`. A row without a tag is a question to answer from `<LIB>`'s own documentation
(never assume the answer: probe it on a known case, `pricebt-discover-the-library`). `A` is the reference stack, `B` is your stack, ratio = B / A. Helpers named here (`first_divergence`, `ratio`) are in `localise-and-bisect.md`.

## 0. First, the ratio and the shape of the difference

| observed ratio or shape | names |
|---|---|
| ratio exactly -1 at every row [control] | a SIGN (holder-signed vs receiver's or payer's point of view) |
| ratio exactly 0.01 or 100 [control] | percent vs decimal (`scale: 100` missing or applied twice) |
| ratio 1e4 or 1e-4 | basis points vs a unit rate (a dv01 "per 1.0" or "per 1bp") |
| ratio equals the notional, or `notional / 1e6`, or 1e6 / notional | a per-unit-of-notional or per-million number where pricebt wants per unit as built |
| ratio 0.99 = 1 - h^2, on a residual only [ledger] | a finite-difference step of h = 0.1 of the move (section 4) |
| constant tiny relative difference (1e-9 .. 1e-6) on every row | interpolation, solver tolerance, rounding: a noise floor to MEASURE, not a bug |
| difference starts at a date and persists | a date effect: holiday, payment date, fixing, roll, start of the swap |
| difference grows with the age of the position | a definition that changes once the instrument has started (dv01 annuity vs ladder sum) |
| difference is one day of interest (notional x rate / 360) on one coupon [QL doc 9.1] | a schedule or payment date one business day off |
| a different number of trades or sizes | a strategy that reads a measure (a band, a sized hedge) sees a different value: fix L2 first |
| everything `exact` or `noise` but you know something is wrong, or `0 positions` in the header | an UNSIZED or tiny position: the shipped floors assume unit-sized templates, so a flipped sign on a payer of notional 1e-3 passes (executed), and a base with no trades passes with nothing compared. Give the base positions of realistic size (1e6 to 1e7 notional), one payer and one receiver, two notionals, and assert `n_positions` |

`pv`, measures and layer `unit` values are PER UNIT AS BUILT (the notional lives in the terms); the engine multiplies by the position `quantity` (verified: a size-3 position has the same audited `pv` and `measure_dv01` per unit and 3x equity and layer `amount`).
An adapter is handed the instrument, the terms and the context (the binding grammar has `@pricer`, `@ctx`, `@instrument`, `@terms.<n>`, `@state.<k>` and no quantity), so a factor that equals the notional (or 1e6 / notional) is the adapter returning a per-unit-of-notional or per-million number.

## 1. L0 (inputs and resolved terms): fix here first, everything below is downstream

| symptom | likely cause | probe | fix |
|---|---|---|---|
| `L0.snapshot_digests` differ, or `info` "no digests recorded" | the two stacks did not read identical snapshots: a live or non-deterministic provider, or a provider whose pricers carry no digest | run the reference twice (`selftest`); print `res.record.audit["inputs"]` of both (`ts, role, digest, stamp`) | freeze the data into a snapshot provider (`pricebt-market-data-snapshots`); the provider emits `MarketSnapshot` with a digest |
| `L0.resolved_terms` `input`, `effective` and `maturity` shifted by ONE business day [control] | calendar or holiday set: the wrap loads a different holiday set than the snapshot's (one too many or too few), or a wrong weekmask | `resolved()` in `regression-test-template.md` on ONE snapshot through both factories; count business days between the two dates in both calendars | build the library calendar from `snapshot.calendars[<name>]` in `wrap`; never a library-named calendar [QL doc 2.1: a named calendar disagreed with the fixture calendar on two dates inside 10Y swaps]; register content-addressed names when the library's registry is global |
| `L0.resolved_terms`, `effective` off by exactly the spot lag | `spot_lag_days` or `payment_lag_days` not mapped (a library default of T+1 or T+2 used instead of the conventions block) | print the resolved `effective` for `fixed_rate: par`, `maturity: 5Y` on a Friday before a holiday Monday | map every conventions key explicitly; raise `CFG-CONVENTION-UNSUPPORTED` for a token you cannot express (`pricebt-instrument-kit`) |
| `L0.resolved_terms`, `maturity` differs for 18M / 30M tenors or explicit dates, `effective` equal | schedule generation: backward generation loses a clamped roll day; the roll of an explicit maturity; short front stub vs back stub; end-of-month [QL doc 2.2, 9.2, 9.8] | resolve the same terms in both stacks and print the roll / unadjusted dates; the whole-year tenors usually agree first | generate the unadjusted dates in adapter code with the reference's rule (roll = effective day clamped to the month, short FRONT stub); pass explicit adjusted dates to the library |
| `L0.resolved_terms`, `fixed_rate` off by 100x or by a spread | `par` resolved in decimals, or at the wrong pricer or date, or `par_spread_bp` applied in percent | resolve `fixed_rate: par` and compare with the `rate` measure of the same swap (they must be equal, in PERCENT) | percent in pricebt; resolve `par` at the FILL pricer inside the factory |
| `L0.conventions_digest` differs | the two runs did not share one conventions block (a `--set` differing per stack cannot happen: `--set` is global), or an adapter mutated the block | print `res.manifest["instruments"][<name>]["conventions"]` for both runs | never write into the conventions dict; copy it |

**A fault that NO report row shows (pin it in a unit test).** A factory that returns the library's ISO strings as `effective` / `maturity` passes `check_resolved` (it accepts a valid ISO string) and the L0 comparison coerces both sides through `pd.Timestamp`, so `'2024-05-29'` equals `dt.date(2024, 5, 29)`
(executed: `from pricebt.tieout.compare import _same` gives `True` for the pair, and `False` for `2024-05-30`; `import pricebt.tieout.compare as c` would bind the `compare` FUNCTION that the package re-exports, not the module): `L0.resolved_terms` stays `exact` and nothing fails. Assert `isinstance(built.terms["effective"], dt.date)` (and `maturity`) in the factory's unit test, and convert with `dt.date.fromisoformat` in the factory.

## 2. L1 (marks: `pv`, `cash`, `financing`, `quantity`)

| symptom | likely cause | probe | fix |
|---|---|---|---|
| `L1.marks_rows` `structure` ("6 rows only in reference") [control] | one stack skipped or failed marks: with `on_error: record` an exception became a recorded error, or the run stopped early | `res.results["B"].errors` (columns `ts, where, position, error`) | fix the exception (often `MarketDataUnavailable`: a missing fixing, section 5) |
| `L1.pv` `exceeds` from the FIRST timestamp, L0 exact, every position | PV definition: day count, compounding, accrual dates, payment lag, schedule, or the curve (interpolation) | one position, one day (`localise-and-bisect.md`); dump both libraries' cashflow tables (dates, accrual fractions, amounts) for that swap | fix the mapping in `conventions.py`; probe the convention on a par swap first: it must be worth 0 |
| `L1.pv` exact until a payment date, then a step; `L1.cash` differs | payment on the reference date, payment lag, cash-sweep rule (a flow paid today is cash, not value) | `first_divergence(A, B, "cash")`; look at the flows around that date | make the value drop equal the cash booked (the kit's `cash_sweep`); library flag for flows on the reference date [QL doc 4: `includeSettlementDateFlows`] |
| `L1.pv` differs once a swap has STARTED; fresh swaps agree | fixings visibility: which fixings the started leg sees. A fixing dated D is published the next business day; a library that uses a stored fixing dated the evaluation date differs [QL doc 4] | compare the first divergence with the effective date; print the fixings each stack was given | pass only fixings dated strictly before the reference date; convert fixing UNITS (percent vs decimal) in the wrap |
| run STOPS: `MarketDataUnavailable ... 1 overnight fixings missing between 2024-05-28 and 2024-06-19; first 2024-06-19` [control] | the wrap loaded no (or too few) holidays: on a weekend-only calendar a market holiday is a business day and needs a fixing | load the snapshot's holidays; `--set backtest.on_error=record` to get a report anyway (`MarketDataUnavailable` is a `PricebtError`, so it is recorded) | as above |
| `L1.pv` differs by 1e-9 .. 1e-6 relative uniformly | interpolation (log-linear in DF vs linear zero rates), curve day basis, DF-to-zero round trip | `test_discount_factors_become_zero_rates...` pattern: round-trip DFs between and beyond the nodes | honour only the snapshot's interpolation TAG and raise `[CFG-INTERPOLATION] curve 'c' has interpolation '...'; this adapter honours only 'log_linear_df'` for the rest |
| `L1.pv` payer and receiver differ by 2x in one direction | direction sign of `side` (pay = +1 payer-positive) applied twice or not at all | payer and receiver in one one-position run | the direction sign lives in the methods (`Valuation` cannot be reached by a binding `sign`) |
| `L1.pv` ratio is the notional or 1e6 / notional | the library values per unit of notional or per million | build one swap with two notionals | multiply by `notional` (or `notional / 1e6`) in the method; a binding `scale` is a constant and cannot read the trade |
| results differ between runs, positions or stack ORDER; self-test fails | process-global state in `<LIB>`: valuation date, calendar registry, fixings store, cached curves, thread state | run the same position twice in one process and in a fresh process; ask `<LIB>` docs which settings are global | set and restore every global inside one guard per call (`_compat.guard`); content-addressed registrations; no state that outlives a call [QL doc 8] |
| `L1.pv` differs by tiny quantised amounts that scale with notional | rounding inside `<LIB>` (rates to n decimals, day fractions, price ticks) | vary the rate by 1e-9 and see whether `pv` moves in steps; read `<LIB>`'s rounding options | switch rounding off if the library allows, else record the floor with a `reason` (`tolerances.md`) |
| `L1.quantity` `exceeds`, hedge strategy | sizes derived from each stack's OWN measured ladder [ledger `swap_book`] | compare `L2.delta_ladder.*` first; then the quantities of the marginal legs | declare `L1.quantity` by name with the measured amplification and a `reason`; otherwise fix L2 |

## 3. L2 (measures: `dv01`, `gamma`, `rate`, `delta_ladder.<bucket>`)

| symptom | likely cause | probe | fix |
|---|---|---|---|
| `L2.dv01` `exceeds`, ratio -1 on every row, L1 exact [control] | the receiver's point of view: `sign: -1` missing on the binding | `ratio(A, B, "measure_dv01")`; the report's `NOT IDENTITY` list shows which bindings carry a sign | `sign: -1.0` on `dv01`, `gamma`, `delta_ladder` and the four layers of the binding block (`pricebt-bindings-cookbook`) |
| `L2.rate` `exceeds`, max rel 0.99 (0.0403 against 4.03) [control] | decimal vs percent: `scale: 100` missing | `ratio(A, B, "measure_rate")` = 0.01 | `scale: 100.0` on `rate`; the strike `percent / 100` in the factory; fixings `unit` in the wrap |
| `L2.dv01` and `L2.gamma` ratio 1e-4 or 1e4 | "per bp" vs "per unit rate": the bump unit | ratio; the schema says `dv01` is currency per +1bp | rescale in the method (a constant `scale` is fine here) |
| `L2.dv01` `exceeds` only for STARTED swaps, growing with age; L1, `L3.delta`, L4 exact [suite] | the definition of `dv01` after the start: analytic fixed-leg annuity (keeps the accrued coupon, which no longer moves with rates) vs the sum of the delta ladder | rebind ONE binding in a stack overlay and re-run (`localise-and-bisect.md`, section 3) | match the reference: annuity before the start, ladder sum after it (`dv01` sum of `delta_ladder` over the bound `tenors`) [QL doc 5] |
| `L2.dv01` differs 1e-3 .. 1e-2 uniformly on aged swaps | a different pillar set: `tenors` overridden on one binding only, or 4 vs 11 pillars [QL doc 5] | print the `tenors` kwargs of `dv01`, `gamma`, `delta_ladder` in the report's binding table | one `tenors` list for all three bindings; `sum(delta_ladder) == dv01` must hold for a started swap |
| `L2.dv01` exceeds by about 1e-4 (1.046e-4 on a seasoned 2Y; 6.6e-3 on a swap with 2 weeks left: the example service's base, 2024-05-24) on the SEASONED or short positions only; with the ladder audited `L2.delta_ladder.<the library's extra bucket>` is `structure` and its neighbour `exceeds`; `L3.tay_delta`, `L3.tay_unexplained` follow; L0, `pv`, `cash`, `rate` and the layers `exact`; your own `tenors` are one list on all three bindings | the LIBRARY's par-risk pillar set is fixed and differs from the reference's (the example service: twelve, 1M to 30Y; the reference: eleven, no 1M): two measures, not a bug | run the reference with the library's list: `tenors` as a kwarg of the reference's `dv01`, `gamma`, `delta_ladder` (`ref_swap.dv01(ctx=ctx, tenors=[...])`) and compare | keep the library's native buckets; align the REFERENCE with a second overlay that changes only `tenors` (and the ladder `keys`); pin the default-reference gap in a test; never declare it: `pricebt-layers-and-ladder`, section "Your library's pillar set is fixed and differs from the reference's" |
| `L2.gamma` off by tens of percent, everything else fine | bump size and solver tolerance: a second difference of a re-solved curve is dominated by solver noise [QL doc 9.7] | run `<LIB>`'s solver to a tighter tolerance and see whether `gamma` converges; vary the bump | tighten the tolerance inside the measure, or use a larger bump; declare the floor with a reason if it stays |
| `L2.delta_ladder.<every bucket>` `structure`, "exists in reference only" [control] | the ladder keys are not canonical tenors (`30y`), or the reducer refused: the audit turned the error into NaN | `errors[errors["where"] == "audit"]["error"]`: `MeasureError: measure 'delta_ladder': key '30y' is not a canonical tenor (upper-case <int><D|W|M|Y>, e.g. '3M', '10Y')` | upper-case the keys in the reducer; declare `keys` exactly; refuse a loaded extra bucket |
| one `delta_ladder.<bucket>` `structure` | the library returns an extra bucket (`on`) or misses one; declared `keys` differ from what comes back | print the raw ladder of one swap | drop an EMPTY extra bucket, refuse a loaded one |
| ladder buckets off by 1e-2 near pillar dates | pillar dating and end-of-month defaults of the bootstrap [QL doc 6, 9.8] | one pillar swap: all its risk must sit in ONE bucket | set the pillar to the termination date and end-of-month to false explicitly |
| `L2.<measure>` `info` "NaN on both sides" | the measure is not bound, or fails in BOTH runs | `errors` of both runs | bind it, or remove it from `audit_measures` |
| `L2.<ladder bucket>` `noise` but you suspect a bug | the floor is absolute below 100: the bucket is small | `t = Tolerances().for_("L2", "delta_ladder", "swap"); t.rel * t.floor` (0.1) against the bucket size | compare the ladder directly against the reference in a unit test to a tight tolerance |

## 4. L3 (layers: `carry`, `roll`, `delta`, `convexity`, `unexplained`, baseline `tay_*`)

| symptom | likely cause | probe | fix |
|---|---|---|---|
| only `L3.tay_delta`, `L3.tay_convexity`, `L3.tay_unexplained` fail; the library layers pass [control] | the baseline reads `dv01`, `gamma`, `rate`: a sign or a unit there (the rate move is turned into bp with the unit the schema declares) | go to L2: which of the three is off, and by what ratio | fix the binding (rows above) |
| ONLY `L3.tay_unexplained` (and `/unit`) exceeds, about 1e-3 relative, while `L2.dv01` and `L3.tay_delta` are `noise` (about 2e-7) and every other row is `exact` or `noise` [executed] | a started swap's `dv01` is the library's own PARALLEL risk (+-1bp) instead of the ladder sum (+-0.5bp per pillar): two recipes that differ by ~2e-7, and `tay_unexplained` is a small residual, so the same absolute error is ~1e-3 of it (measured 1.174e-3 against 1e-3) | compare the bound `dv01` of a started swap with `sum(delta_ladder)` (`dv01_consistency.py` prints `gap to ladder` 1e-8 instead of 0) | bind the ladder sum for started swaps, in every stack (`pricebt-layers-and-ladder`, `dv01-one-definition.md` of `pricebt-layers-and-ladder`, rule 2); do not widen `L3.tay_unexplained` |
| `L3.layer_definitions` `info` ("the layer ids and versions differ between the stacks") | your layers are declared with another id or version: DIFFERENT definitions, not a difference to tolerate | compare `res.manifest["instruments"][<n>]["layers"]` of the two runs | compare invariants (the kit) and the baseline; use the ADR 005 definitions (`pricebt-layers-and-ladder`) |
| `L3.carry` / `L3.roll` differ | carry = the t0 world's flows valued at t1; roll = the curve unchanged in tenor space anchored at t1 INCLUDING realised fixings | run the kit on a seasoned swap across a payment date | implement the definitions literally |
| `L3.unexplained` is 0.99 x the reference's, layers agree [ledger] | finite-difference step: the directional derivatives are taken by central differences of step h = 0.1 of the move, so `delta` absorbs h^2 of the third-order remainder | `tools/probe_unexplained_ratio.py` (worked-examples.md) | declare `L3.unexplained` `rel` about 1.5 x h^2 with the mechanism as `reason`; or take exact directional derivatives |
| `L3.unexplained` large, layers plausible | the layers do not sum to the P&L: one layer misses a component | `KitReport.unexplained_share`; `res.reconcile()` | fix the layer that fails the kit |
| `reconcile[<stack>]` `exceeds` | that run's own ledger identity fails (the note names the checks) | `res.reconcile().checks` for the failing names | not a cross-stack difference: the run itself is inconsistent (a pv of a position not booked, a flow lost) |

## 5. L4 (portfolio) and whole-run symptoms

| symptom | likely cause | probe | fix |
|---|---|---|---|
| `L4.trade_ledger_structure` `structure` ("N trades in A, M in B" or "quantity differs at trade k") | a trigger or a sizing rule reads a measure that differs (a dv01 band, a hedge): different trades [suite: 76 rebalances instead of 24] | find the L2 difference that the strategy reads | fix L2; for a risk-sized strategy declare `L1.quantity` |
| `L4.stats` and `L4.stats_traded` `exceeds` while every other row is `input` [control] | an L0 difference explains the run, but the statistic rows are keyed by name and cannot be attributed | L0 first | fix the L0 difference; do not widen |
| `L4.equity` `exceeds`, everything below L4 exact | a cash, cost or financing difference: `financing`, the cash accrual, or the ledger | `first_divergence(A, B, "cash")`; `res.reconcile()` | as L1 |
| the run raises in one stack, no report [control] | `MarketDataUnavailable`, a `CFG-*` at build, an exception in the library | the CLI's `error: [...]` line. `--set backtest.on_error=record` turns a `PricebtError` raised while marking or executing (`MarketDataUnavailable`, `MethodCallError`, `MeasureError`) into a report; it does NOT record a raw library exception (`error: [RuntimeError] ...` still exits 2) nor a `CFG-*` raised while loading or building the config | fix the cause; translate library exceptions in the adapter (`acme_adapter/_compat.py: translate`); `record` is a diagnostic aid |
| `binding 'value': method 'value' called with args=[] kwargs=['ctx']: ...` | a `TypeError` INSIDE your callable, worded like a signature mismatch | read to the end of the message; [CE-TYPEERROR](../../pricebt-wire-external-library/references/common-errors.md#ce-typeerror) | fix the body |
| harness self-test fails | non-determinism (a live source, a random seed, a global, a cache keyed by `id()`) | run twice, diff `res.record.audit["marks"]` | remove the source of non-determinism; pin objects that are keyed by `id(self)` |
| `[CFG-ALLOW] ... is not under an allowed prefix ['pricebt']` | the base has no `registry.allow` for your package (or an overlay carries it) | [CE-ALLOW](../../pricebt-wire-external-library/references/common-errors.md#ce-allow) | BASE config only |

## 6. Questions to put to `<LIB>`'s documentation (each must be answered by a probe on a known case, never assumed)

1. What is the calendar model (weekmask, holiday list, horizon) and is it global? What is the spot lag rule and the business-day convention for schedule ends and payments?
2. Which day count, compounding, payment lag, stub and end-of-month rules does a swap built from `<LIB>`'s defaults use, and which of them does the conventions block map to explicit arguments?
3. Which fixings does a started swap see on the reference date, in which unit, and does a fixing dated the reference date count?
4. What interpolation does the curve object use, and can it be forced to the snapshot's tag?
5. Which numbers are reported from whose point of view (payer, receiver, holder), in which unit (decimal or percent, per unit, per million, per bp) and per what notional?
6. What does `<LIB>`'s risk function bump (par rates, zero rates, quotes), by how much, and what is the solver tolerance?
7. Which process-global state exists (valuation date, calendars, fixings, caches, licence or session state) and what must be restored after every call?
8. Does `<LIB>` round any input or output?
